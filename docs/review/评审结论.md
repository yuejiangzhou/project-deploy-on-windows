## 二、四个角色的核心发现

### 技术架构师
- 架构无需大改，但需补充**安全层**（Spring Security + JWT）
- 打包引擎建议改为**责任链模式**以支持组件扩展
- 推荐开发顺序：安全认证 → License 核心 → 打包增强 → UI 改造

### 后端开发
- **总改造量约 20 人天**（~1 个月）
- PRD 字段名（`mysql_username`）与现有代码（`dbUsername`）不一致，需统一
- 分片上传基本满足需求，但缺少进度查询和 MD5 校验
- Spring Security 与 @Async 打包任务的 SecurityContext 传递需特殊处理

### 前端开发
- **总改造量约 19 人天**（~4 周）
- 需新增 MainLayout 消除布局重复代码
- InfraTabContent.vue 是死代码，需决定复用或删除
- Pinia store 需新建 user/permission/license 三个

### DevOps
- **.ps1 改 .bat 强烈反对**：健康检查、PID 管理、MySQL 安全初始化在 .bat 中几乎不可维护
- 建议保留 PowerShell，设 Windows 10+ 最低要求
- Redis 推荐 tporadowski/redis 社区版
- 打包体积预估 800MB-1GB+，建议分层打包 + 增量更新

## 三、已决策的关键问题

| 序号 | 议题 | 决策 | 依据 |
|------|------|------|------|
| **Q1** | 启动脚本方案 | ✅ **.bat + .ps1 混合** | `start.bat` 作为 bootstrap 调用 `start_services.ps1`，客户双击 .bat，复杂逻辑用 PowerShell |
| **Q2** | 数据库字段命名对齐 | ✅ **统一用现有命名**（`dbUsername`/`dbPassword`/`minioAccessKey`/`minioSecretKey`） | PRD 更新，前端适配现有后端字段 |
| **Q3** | Redis Windows 版方案 | ✅ **tporadowski/redis 社区版** | 开源可用，风险已记录 |
| **Q4** | 端口冲突处理 | ✅ **开发配置冷门端口 + 自定义端口** | 端口冲突概率低，冲突时开发手动改，无需系统检测 |
| **Q5** | 路径处理 | ✅ **相对路径** | 脚本中使用 `$PSScriptRoot` 相对路径，避免中文/空格问题 |
| **Q6** | Nginx 端口 | ✅ **开发自定义端口，非 80** | 通过 nginx.conf 编辑功能自定义，避免 UAC 问题 |
| **Q7** | License 机制 | ✅ **已明确** | RSA-2048 签名 + AES 时间戳 + `--validate-only` 预检，三层防护 |
| **Q8** | PID 进程管理 | ✅ **taskkill /F /T /PID** | 按进程树杀死子进程，比 Stop-Process 更可靠 |
