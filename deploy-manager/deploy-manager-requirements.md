# DeployManager 需求文档

> 本文档基于 `deploy-manager/pages/` 下的 4 个原型 HTML 页面编写，描述系统的功能需求与业务规则，作为开发的依据。如原型与本说明冲突，以原型视觉效果为准。

---

## 1. 项目概述

### 1.1 产品定位

DeployManager 是面向公司内部开发人员的**多产品部署打包管理系统**。将各产品的 Java 后端（JAR）、Vue 前端产物（dist）、MySQL 数据库便携包、MinIO 对象存储、Nginx Web 服务器及可选的 UnSim 引擎，统一打包为**加密 ZIP**，交由运维/销售人员部署到客户 Windows 环境。

### 1.2 核心业务流程

```
开发上传资源(项目文件 + 基础组件) → 配置项目(选版本/端口/账密) → 打包生成加密ZIP → 运维下载ZIP → 客户Windows解压部署
```

### 1.3 用户角色

| 角色 | 说明 |
|------|------|
| 开发人员 | 上传项目文件与基础组件、配置项目、发起打包 |
| 运维/销售 | 下载打包产物，交付客户 |

### 1.4 设计原型

| 页面 | 原型文件 | 路由 |
|------|---------|------|
| 项目管理 | `project-list.html` | `/projects` |
| 项目配置 | `project-config.html` | `/projects/:id/config` |
| 资源上传 | `resource-upload.html` | `/upload` |
| 打包中心 | `package-center.html` | `/projects/:id/package` |

## 3. 功能需求

### 3.1 项目管理页

#### 3.1.1 页面结构

```
标题行：「项目管理」+ [新建项目]
统计卡片行：2 卡片（总项目数-蓝、已打包数-绿）
搜索栏：单一搜索输入框
项目表格：项目名称 | JAR包 | Vue前端 | 状态 | 操作
分页器
```

#### 3.1.2 功能点

| 编号 | 功能 | 说明 |
|------|------|------|
| F1.1 | 新建项目 | 弹窗：项目名称（必填）+ 项目描述（选填）；取消/创建按钮 |
| F1.3 | 项目列表 | 表格展示项目，每行带动态图标（按项目类型区分图标与背景色） |
| F1.4 | 项目图标 | 根据项目类型自动匹配 Lucide 图标（如电商=shopping-cart、数据=database、用户=users） |
| F1.5 | 统计卡片 | 总项目数（蓝色数字）、已打包数（绿色数字，仅统计成功打包） |
| F1.6 | 搜索 | 实时按项目名称过滤 |
| F1.7 | 行操作 | [配置]蓝 / [打包]绿 / [下载最新版本]边框 / [删除]灰 |
| F1.8 | 下载最新版本 | 若项目无历史成功打包产物，弹出提示框告知用户先完成配置和打包；有产物则直接下载 |
| F1.9 | 删除项目 | 二次确认弹窗后删除 |
| F1.10 | 分页 | 表格底部「共 N 条记录」+ 上一页/页码/下一页 |

#### 3.1.3 状态定义

- **Vue 前端**：已配置（绿）/ 未配置（灰）
- **项目状态**：已就绪（绿）/ 配置中（蓝）/ 已归档（灰）
- **JAR 包列**：显示 jar 文件名（等宽字体）或「未上传」（灰）

#### 3.1.4 交互

- 「配置」→ `/projects/:id/config`
- 「打包」→ `/projects/:id/package`
- 「下载最新版本」→ 若有成功打包产物则下载，否则弹出提示框（含"前往配置"和"我知道了"按钮）
- 「新建项目」→ Modal → 创建后刷新列表

### 3.2 项目配置页

#### 3.2.1 页面结构

```
页面标题：「{项目名} - 项目配置」+ 副标题
顶部栏：「前往打包中心」按钮
Section A：项目文件（JAR包 + 应用端口/JVM参数 + Vue前端产物）
Section B：基础组件（版本选择）— JDK / MySQL / MinIO / Nginx
Section C：可选组件 — UnSim引擎
Section D：脚本结构预览（深色卡片）
[保存配置] 按钮
```

#### 3.2.2 Section A：项目文件

| 字段 | 控件 | 说明 |
|------|------|------|
| JAR 包 | 路径下拉选择器 | 按路径分组列出可选 JAR 文件，显示「路径 + 文件名 + 大小」 |
| 应用端口 | 数字输入 | 默认 8080，内联在 JAR 下方灰色框 |
| JVM 参数 | 文本输入 | 默认 `-Xms512m -Xmx2048m`，等宽字体 |
| Vue 前端产物 | 路径下拉选择器 | 列出可选 dist 文件夹，显示「路径 + 文件夹名 + 大小 + 文件数」 |
| 管理文件 | 链接 | 跳转资源上传页对应文件夹 |

**路径下拉选择器**：
- 触发器显示两行：灰色等宽路径 + 文件名（含大小）
- 展开面板按路径分组，每组有路径标签 + 文件列表
- 选中项蓝色高亮

#### 3.2.3 Section B：基础组件（版本选择）

> **重要**：基础组件支持**多版本选择**，不再是固定单一版本。每个组件有版本下拉，可选不同版本及标签。

**JDK**
- 版本下拉：显示「版本名 — 标签 (大小)」
- 选项示例：JDK 17.0.2 稳定版 / JDK 11.0.16 兼容版 / JDK 8u431 旧版兼容 / JDK 21.0.1 最新版
- 每项含：版本号、标签、大小、状态点（纯净版=绿点）
- 无端口/账密配置

**MySQL**
- 版本下拉分两组：
  - 通用版本：8.0.35 推荐 / 5.7.44 兼容版 / 8.4.3 最新版（均为纯净版）
  - {项目名}专属：8.0.35 含电商初始化数据（已初始化）
- 每项含：版本号、标签、大小、状态点（纯净版=绿点 / 已初始化=蓝点）
- **配置状态联动**：
  - 选「纯净版」→ 显示端口、账号、密码输入框（在项目配置中统一设置，打包时注入）
  - 选「已初始化」→ 显示蓝色提示「使用包内已有配置（端口、账密），系统不再覆盖」

**MinIO**
- 版本下拉分两组：
  - 通用版本：2024.06 通用版 / 2024.03 旧版（纯净版）
  - {项目名}专属：2024.06 含电商 Bucket 策略（已初始化）
- **配置状态联动**（同 MySQL）：
  - 纯净版 → API 端口、Console 端口、账号、密码可编辑（在项目配置中统一设置）
  - 已初始化 → 蓝色提示「使用包内已有配置」

**Nginx**
- 版本下拉：1.24 稳定版 / 1.26 最新版 / 1.18 旧版
- 「编辑 nginx.conf」按钮 → 打开代码编辑器 Modal
- 提示文字：「端口和路由规则在配置文件中定义，打包时自动覆盖」

**Nginx.conf 编辑器 Modal**
- 800px 宽，深色编辑区（`#1E293B` 背景，等宽字体）
- 内容示例：`server { listen 80; ... location /api/ { proxy_pass ...; } }`
- 底部：取消 / 保存（保存后 Toast 提示「nginx.conf 已保存」）

#### 3.2.4 Section C：可选组件

**UnSim 引擎**
- 复选框（是否包含）
- 版本下拉：v3.2 / v3.1 / v2.8
- 端口输入：默认 8090

#### 3.2.5 Section D：脚本结构预览

- 深色卡片（`#1E293B`）
- 等宽字体目录树：
  ```
  /
  ├── start.ps1               (总启动 - 按勾选启动服务)
  ├── stop.ps1                (总停止 - 根据PID杀死服务)
  ├── services/
  │   ├── start-jar.ps1       (→ pid/jar.pid)
  │   ├── start-mysql.ps1     (→ pid/mysql.pid)
  │   ├── start-minio.ps1     (→ pid/minio.pid)
  │   ├── start-nginx.ps1
  │   ├── start-engine.ps1    (→ pid/engine.pid)
  │   └── stop-*.ps1
  └── pid/
      jar.pid, mysql.pid, minio.pid, engine.pid
  ```
- 底部提示：「每个服务启动后记录PID，停止时根据PID精确终止进程」

#### 3.2.6 交互

- 「前往打包中心」→ `/projects/:id/package`
- 「保存配置」→ POST 配置到后端
- 版本下拉选择后联动显示对应配置状态

## 4. 业务规则

### 4.1 项目文件管理

1. 项目文件按**两级目录**组织：`项目名 / 类型(JAR包 | Vue产物)`
2. 上传时需填写**版本标签**（如 v2.1.0）
3. 同版本标签的文件覆盖同名文件（前端警告提示）
4. JAR 包为单文件上传，Vue 产物为文件夹上传

### 4.2 基础组件管理

1. 基础组件支持**多版本管理**，每个组件可上传多个版本
2. 每个版本包含：版本号、标签、初始化状态、所属系统
3. **初始化状态**两类：
   - 纯净版：打包时由系统注入项目配置中的端口和账密
   - 含初始化数据：包内预置配置/数据，系统不再覆盖
4. **所属系统**：通用版本所有项目可选；专属版本仅对应项目可选
5. JDK / Nginx / 引擎仅支持纯净版
6. JDK / Nginx / 引擎本身即为通用组件，无需区分所属系统
7. MySQL / MinIO 支持纯净版与含初始化数据两种

### 4.3 项目配置规则

1. 每个项目只有一套配置
2. 基础组件（JDK/MySQL/MinIO/Nginx）固定包含，但**版本可选**
3. 引擎为可选组件，通过复选框控制
4. 选「纯净版」MySQL/MinIO 时，可配置端口和账密
5. 选「已初始化」MySQL/MinIO 时，使用包内配置，不可修改
6. Nginx 端口和路由通过 nginx.conf 管理，不单独配置端口
7. SQL 脚本仅用于系统内 MySQL 初始化，**不打包到 ZIP 中**

### 4.4 打包规则

1. 打包中心所有配置为**只读**，不可修改
2. ZIP 加密始终开启，密码由用户输入
3. 启动脚本由后端根据配置自动生成
4. 打包为异步任务，前端轮询获取进度
5. 打包产物存储在 MinIO，通过接口下载
6. 产物支持下载和删除，可按状态筛选

### 4.5 项目状态规则

- 新建项目 → `CONFIGURING`
- 配置完成（JAR 已选 + 端口已填）→ `READY`
- 支持手动归档为 `ARCHIVED`

## 6. 与 dev-spec.md 的主要差异

> 以下为原型设计与已有 `deploy-manager-dev-spec.md` 的差异点，开发时以原型为准。

| 差异项 | dev-spec 描述 | 原型实际设计 |
|--------|--------------|-------------|
| 基础组件版本 | 固定单一版本，不可更改 | **支持多版本选择**，版本下拉 |
| 项目文件目录 | 三级（项目/类型/日期） | **两级**（项目/类型），用版本标签替代日期 |
| 基础组件属性 | 仅文件名/大小/时间 | 新增**初始化状态**(纯净版/已初始化)、**所属系统** |
| MySQL/MinIO 账密 | 「账密已内置」不可改 | 纯净版在项目配置中设置端口和账密（非上传时指定）；已初始化版使用包内配置 |
| Nginx 配置 | 上传 nginx_conf 文件 | **nginx.conf 编辑器 Modal** 在线编辑 |

## 7. 数据模型概述（基于原型推导）

### 7.1 新增/调整字段建议

**uploaded_file 表新增**：
